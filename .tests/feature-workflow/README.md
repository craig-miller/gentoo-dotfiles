# Feature workflow checks

```sh
python3 -B -m unittest discover -s .tests/feature-workflow -p 'test_*.py'
bun test ./.tests/feature-workflow/*.test.ts
NODE_PATH=/home/craig/.bun/install/global/node_modules bun .tests/feature-workflow/typecheck.ts
python3 -B .tests/feature-workflow/phase_native_smoke.py
python3 -B .tests/feature-workflow/herdr_popup_smoke.py --ui-only
python3 -B .tests/feature-workflow/herdr_coordinator_smoke.py
python3 -B .tests/feature-workflow/herdr_coordinator_smoke.py --attachment
```

Phase checks add real isolated Git/Stax branches plus mocked endpoint faults: clean/index/busy/queued refusal, expected HEAD/parent/revision, immutable receipt/record/transcript checks, exclusive branch/delivery claims, compaction success/failure, partial branch reconciliation, missing persistence, stale epoch/branch/ACK rejection, subsequent phases and explicit same-session reporting renewal. The new native phase script uses private HOME/config/data/state under ignored `.tmp/`, a named sound-suppressed Herdr PTY, the installed Pi runtime and the offline provider. It checks actual compaction and failure callbacks, transcript retention, same pane/tab/session/worktree, real Stax parent/HEAD, persisted one-time assignment and reporting before/after reload. It retains failure evidence and stops only its own server. These are synthetic tests, not live acceptance.

Follow-up checks cover initial/legacy and phase/renewed bindings, dirty progress preservation, busy/pending/modal queue-or-reject, exact authorization/provenance, command-like text remaining plain content, request-key idempotency/conflicts, identity/revision/server/transcript drift, claim-before-delivery, uncertain persistence/recovery and pinned settlement reporting. Context-policy checks cover known/unknown usage, the advisory 70% threshold, explicit decisions and stale-observation rejection. Explicit-mode tests extend that coverage to both `steer` and `followUp`: idle turn start, correct streaming boundary, concurrent timer/boundary deduplication, delayed/failed acknowledgements, stale/replaced/reloaded endpoints and phase drift. The combined native phase script delivers both modes through real Pi and uses an explicitly selected offline tool fixture (bounded sleep/printf calls) to prove ordering: steer after both current tools but before the next model request; followUp after all subsequent tool/model work. No tool is aborted. It also checks modal deferral, tool exposure, no focus movement, persisted one-time delivery, original receipt/transcript retention and both modes after phase renewal. It is one synthetic candidate test, not the combined human acceptance gate.

Enrollment checks cover ordinary Git/non-Git/non-Herdr sessions (no registration, Git probe or inbox timer), explicit activation, exact durable reload/resume, non-inheritance across new/fork and inherited-argv reload, deliberate launcher roles, minimal legacy receipts, stale identity/role refusal, current completed attachment/phase migration, pointer drift and sequential startup-hook/cancellation races. Native coordinator checks additionally start ordinary Git and non-Git Pi sessions with the candidate loaded, activate only the intended coordinator through its command, and verify durable enrollment across reload. No repository-content classification is involved. See [opt-in candidate evidence](enrollment-notes.md).

Freshness supplement: `test_freshness.py` uses synthetic repositories and local tracking refs (no network) for whole-stack/base inclusion, intermediate/descendant levels, non-main bases, dirty preservation, upstream divergence, acceptance-checkpoint changes, identity drift, evidence expiry and validation diagnostics. Popup unit coverage checks long diagnostic scrolling. Review lifecycle tests mock the read-only checker/Herdr boundary to prove pre-snapshot/pre-launch refusal, post-review freshness checks and renewed explicit sync evidence without relaunch. No native/live review or new live client was opened for this supplement. See [supplement evidence](freshness-notes.md).

See [implementation evidence and integration notes](phase-transition-notes.md) for source-policy collisions and unsupported recovery cases.

Native checks use named Herdr PTYs and disposable synthetic repositories, never desktop windows or existing panes. The coordinator smoke uses an isolated Pi configuration, the installed Herdr integration read-only, and `offline-provider.ts`: deterministic text, no network or real inference. Coordinator/launcher cases execute no model-requested tools; only the explicit native messaging fixture exercises real bounded sleep/printf tools. It checks actual registration, coordinator/worker startup, API delivery, report acknowledgement and focus, not real-model task performance. `--attachment` additionally checks legacy reporting attachment, committed/dirty progress, busy queues, same-session reload/explicit renewal, rebind and rejection of late old-owner reports. Test-only file controls invoke Pi APIs for explicit enrollment and deterministic turns/reload in disposable sessions, never terminal-pasted prompts.

The popup UI-only check intentionally removes `PI_CODING_AGENT_DIR` to cover popup children bypassing Fish configuration. Omitting `--ui-only` makes real provider requests and requires separate authorization. Never load the test provider/trust hook in live agents. Native scripts dispose only resources they create; failure logs are under `/tmp/feature-*-*.log`.
